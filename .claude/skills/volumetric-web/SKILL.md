# Объёмный веб-визуал

## 0. Сначала разбор материала
- Видео-референсы режем на кадры: `ffmpeg -vf "fps=20/длительность,scale=360:-1,tile=5x4"`. Смотрим лист целиком, называем: материал, движение, камера, свет, цвет.
- Чужое видео не вставляем на сайт: это чужая работа. Воссоздаём тот же эффект своим рендером. Оригинал ставим только с разрешения автора.

## 1. Что делает картинку объёмной (проверять каждый экран)
1. Настоящая глубина: объекты в 3D-сцене (Three.js), камера с перспективой, медленный облёт или параллакс за курсором. Плоский canvas 2D с точками не считается.
2. Слои: фон (видео/туман), средний план (3D-объект), передний план (частицы ближе к камере, крупнее и размытее), интерфейс.
3. Свет: аддитивное смешивание, ядро ярче краёв, пульс света изнутри, тень и ореол под объектом.
4. Воздух: затухание по глубине (fog), мелкая пыль, зерно.
5. Интерфейс тоже объёмный: карточки с перспективным наклоном за курсором и бликом, тень с цветом палитры, вход из глубины (translateZ/scale), а не «снизу вверх».

## 2. Приёмы, проверенные в работе
- Облако-огонь из волокон (как @incrprl.dsgn): ~2000 нитей × 30 точек, нити строятся шагами по шумовому полю на CPU один раз, в вершинном шейдере смещение simplex-шумом по времени; цвет: серые волокна + горячее ядро (красное/синее по стороне), пульс 0.5–1.5 Гц; `THREE.Points`, `AdditiveBlending`, `depthWrite:false`, размер точки с затуханием по глубине.
- Сборка из частиц (как «−2 000 000 → +4 000 000»): цели берутся из пикселей текста/прямоугольника (рисуем во внеэкранный canvas, берём каждый n-й пиксель), частицы летят из вихря к целям, затем элемент проявляется, частицы гаснут. Для карточек: контур каждые 6 px + сетка внутри каждые 14 px. Для заголовков: каждое слово рисуем шрифтом элемента по его прямоугольнику.
- Переходы глав: вспышка-блик по экрану, смена слоя фона, номер главы в шапке.

## 3. Источники на GitHub (проверенные)
- three.js examples: webgl_points_*, webgl_gpgpu_*, webgl_postprocessing_unreal_bloom (UMD сборка: cdn.jsdelivr.net/npm/three@0.147.0/build/three.min.js).
- lygia (patriciogonzalezvivo/lygia): готовые шумы, curl, sdf для шейдеров.
- Curl noise (Bridson 2007) для «живого» дыма без симуляции.

## 4. Рендер в видео (когда нужен файл, а не живой WebGL)
- Шейдер/сцену рендерим кадрами в headless Chromium (`--use-angle=swiftshader`), `canvas.toDataURL` по фиксированному времени t = 2π·i/N для бесшовной петли, потом `ffmpeg -c:v libx264 -crf 24 -pix_fmt yuv420p -movflags +faststart`. Два файла: 1600×900 и 720×1280, постер — первый кадр.
- Перекраска готового видео: `hue=h=…`, или попиксельно в numpy по маске цвета.

## 5. Монтаж
- Ритм: вход 1.5–2.5 с, удержание, выход. Одинаковых появлений на соседних блоках нет.
- Каждая глава: свой переход (сборка из частиц, маска по словам, шторка, вспышка).
- Огонь/яркий объект никогда не под мелким текстом: локальная тёмная подложка или смещение объекта.

## 6. Проверка перед выдачей
- Скриншоты 1440 и 390 каждой главы, нет горизонтальной прокрутки, нет ошибок в консоли.
- Headless не играет H.264: проверять по постеру. WebGL проверять в SwiftShader.
- `overflow:hidden` на секции ломает прокрутку по слайдам (scroll-snap): использовать `overflow:clip`.
- Сверить с вопросом «где здесь глубина?» на каждом экране. Нет ответа — переделать.
